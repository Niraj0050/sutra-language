# पुस्तकालय — सूत्र मानक-पुस्तकालय

सूत्र में लिखे पुनःप्रयोज्य मॉड्यूल। कोई C नहीं — सब कुछ सूत्र, native +
interpreter दोनों पर समान चलता है।

```sutra
आयात "पुस्तकालय/मानक.सूत्र";      // सब १२ मॉड्यूल एक साथ
// या सिर्फ़ जो चाहिए:
आयात "पुस्तकालय/सूची.सूत्र";
```

**मॉड्यूल:** सूची · शब्दकोश · पाठ · समुच्चय · ढेर · कतार · गणित · प्रारूप ·
जेसन · सीएसवी · क्रमचय · ढेर_प्राथमिकता · परीक्षण · पथ · तर्क · तिथि · यूआई ·
व्यंजक · एसएचए256 · संकुचन · यादृच्छिक · बेस64 · यूआईडी · विन32 · थ्रेड · संजाल
(अंतिम तीन Windows-only + FFI-आधारित — `मानक.सूत्र` में शामिल नहीं)

आयात-मार्ग आयात करने वाली सञ्चिका के सापेक्ष हल होता है; रेपो-मूल से चलाओ
या `पुस्तकालय/` को अपने प्रोजेक्ट में कॉपी करो।

---

## सूची.सूत्र — सूची (list) संक्रियाएँ

सब कार्य **नई सूची** लौटाते हैं; मूल अछूती। तुलना (`< > ==`) पाठ और संख्या
दोनों पर सही, तो क्रमबद्ध/खोज मिश्रित-समरूप सूची पर चलती हैं।

| कार्य | काम |
|---|---|
| `उलटा(स)` | उल्टा क्रम |
| `योग(स)` · `गुणनफल(स)` | तत्वों का योग / गुणनफल |
| `न्यूनतम_का(स)` · `अधिकतम_का(स)` | सबसे छोटा / बड़ा तत्व (रिक्त → शून्यम्) |
| `समाहित(स, म)` | क्या म सूची में है (बूल) |
| `अनुक्रमणिका_की(स, म)` | म का पहला अनुक्रमांक, वरना −1 |
| `गणना_की(स, म)` | म कितनी बार |
| `अद्वितीय(स)` | डुप्लिकेट हटाओ (क्रम बना रहे) |
| `समतल(स)` | एक स्तर समतल: `[[1,2],[3]]` → `[1,2,3]` |
| `टुकड़े(स, आकार)` | आकार-आकार के भागों में बाँटो |
| `श्रेणी(आ, अं)` · `श्रेणी_चरण(आ, अं, च)` | पूर्णांक श्रेणी `[आ, अं)` |
| `भरो(गिन, म)` | म की गिन प्रतियाँ |
| `पहला(स)` · `पिछला(स)` | पहला / अंतिम तत्व |
| `लो(स, गिन)` · `छोड़ो(स, गिन)` | पहले गिन / पहले गिन छोड़कर |
| `खंड(स, आ, अं)` | उप-सूची `[आ, अं)` |
| `सब_सत्य(स)` · `कोई_सत्य(स)` | सब/कोई तत्व सत्य |
| `युग्म(अ, ब)` | `zip` — `[[a0,b0], ...]` |
| `सपाट_जोड़(सूचियाँ)` | सूचियों की सूची को एक में |
| `क्रमबद्ध(स)` · `क्रमबद्ध_अवरोही(स)` | मर्ज-सॉर्ट (स्थिर, O(n log n)) |
| `है_क्रमित(स)` | क्या आरोही क्रम में |
| `द्विआधारी_खोज(स, लक्ष्य)` | क्रमबद्ध सूची में binary search → अनुक्रमांक / −1 |

## शब्दकोश.सूत्र — शब्दकोश (map) संक्रियाएँ

| कार्य | काम |
|---|---|
| `मान_सूची(द)` | सारे मान (कुंजी-क्रम में) |
| `युग्म_सूची(द)` | `[[कुंजी, मान], ...]` |
| `विलय(अ, ब)` | दो शब्दकोश मिलाओ (ब हावी) |
| `उलट(द)` | कुंजी ↔ मान |
| `से_युग्म(युग्म)` | `[[क, म], ...]` से शब्दकोश |
| `चुनो(द, कुंजियाँ)` · `छोड़ो_कुंजियाँ(द, कुंजियाँ)` | pick / omit |
| `कुंजी_हटाओ(द, कुंजी)` | कुंजी हटाकर नया (अंतर्निहित `हटाएं` native में नहीं) |
| `कुंजी_गणना(द)` · `शब्दकोश_खाली_है(द)` | गिनती / रिक्तता |
| `कुंजी_का(द, म)` · `प्रतिलिपि(द)` | मान की कुंजी / उथली प्रति |

**कुंजी-क्रम चेतावनी:** interpreter (C++ host) `कुंजियाँ()` को उल्टे क्रम
में देता, native डालने के क्रम में। C++ host अब build नहीं होता तो वह
अभी ठीक नहीं हो सकता — कुंजी-क्रम पर निर्भर मत रहो (या `क्रमबद्ध()` से
normalise करो)।

## पाठ.सूत्र — पाठ (string) संक्रियाएँ

| कार्य | काम |
|---|---|
| `दोहराओ(स, गिन)` | स को गिन बार |
| `बाएँ_भरो(स, लं, भरण)` · `दाएँ_भरो(...)` | pad-start / pad-end |
| `उलटा_पाठ(स)` | अक्षरों का उल्टा क्रम |
| `पंक्तियाँ(स)` | नई-पंक्ति पर विभाजित |
| `है_रिक्त(स)` | रिक्त या केवल श्वेत-स्थान |
| `समाहित_पाठ(स, उप)` | क्या उप-पाठ है (बूल) |
| `गिनो_पाठ(स, उप)` | उप कितनी बार (गैर-अतिव्यापी) |
| `बड़ा_प्रथम(स)` · `शीर्षक_रूप(स)` | capitalize / title-case |
| `अक्षर_पर(स, सूचकांक)` · `अक्षर_सूची(स)` | char-at / अक्षरों की सूची |
| `उपसर्ग_हटाओ(स, उ)` · `प्रत्यय_हटाओ(स, प)` | strip prefix / suffix |
| `सब_बदलो(स, पुराना, नया)` | सारी उपस्थितियाँ बदलो |

## समुच्चय.सूत्र — समुच्चय (Set)

```sutra
मान स = नवीन समुच्चय();
स.जोड़ो(३); स.जोड़ो(३); स.जोड़ो(५);
स.है(३)        // सत्य
स.आकार()       // २
स.सूची_में()   // [३, ५]  (डालने का क्रम)
स.हटाओ(३); स.खाली_है();
```

मुक्त कार्य: `समुच्चय_से_सूची(सूची)`, और `संघ(अ, ब)` / `प्रतिच्छेद(अ, ब)` /
`अंतर(अ, ब)` — ये **सूची लौटाते हैं** (नीचे "सीमाएँ" देखो)।

## ढेर.सूत्र — ढेर (Stack, LIFO)

```sutra
मान ढ = नवीन ढेर();
ढ.धकेलो(१); ढ.धकेलो(२);
ढ.निकालो()   // २  (हट जाता है)
ढ.झाँको()    // १  (हटता नहीं)
ढ.आकार();  ढ.खाली_है();
```

## कतार.सूत्र — कतार (Queue, FIFO)

```sutra
मान क = नवीन कतार();
क.डालो(१); क.डालो(२);
क.निकालो()   // १
क.आगे()      // २  (हटता नहीं)
क.आकार();  क.खाली_है();
```
भीतर सूची + शीर्ष-सूचक (amortised O(1) `निकालो`, समय-समय पर संकुचन)।

## गणित.सूत्र — संख्या-सिद्धांत, सांख्यिकी, PRNG

| कार्य | काम |
|---|---|
| `पूर्ण_निरपेक्ष` `चिह्न` `परिसीमन` `सम_है` `विषम_है` | पूर्णांक उपयोगिताएँ |
| `पूर्णांक_भाग(अ,ब)` `गणित_शेष(अ,ब)` | floor-div / गणितीय शेष (ऋणात्मक-सुरक्षित) |
| `घातांक(अ,घ)` `गुणनखंड(क)` `फिबोनाची(क)` | पूर्णांक घात / factorial / n-वाँ फ़िबो |
| `गसो(अ,ब)` `लसो(अ,ब)` | gcd / lcm |
| `अभाज्य_है(क)` `अभाज्य_गुणनखंड(क)` `अभाज्य_तक(सीमा)` | प्राइम जाँच / गुणनखंड / सूची |
| `औसत` `माध्यिका` `बहुलक` `प्रसरण` `मानक_विचलन` `परिसर` | सांख्यिकी (संख्या-सूची) |
| `यादृच्छिक_बीज(न)` `यादृच्छिक_अगला()` `यादृच्छिक()` | बीज-योग्य PRNG (MINSTD, नियतात्मक) |
| `यादृच्छिक_परास(न्यून,उच्च)` `यादृच्छिक_तत्व(स)` `फेंटो(स)` | पूर्णांक-परास / random pick / Fisher-Yates |

## प्रारूप.सूत्र — पाठ-प्रारूपण

| कार्य | काम |
|---|---|
| `प्रारूप("{} + {} = {}", [2,3,5])` | टेम्पलेट (f-string सम) → `"2 + 3 = 5"` |
| `बाएँ_संरेखित` `दाएँ_संरेखित` `मध्य_संरेखित(स,चौड़ाई,भरण)` | padding |
| `हज़ार_विभाजक(1234567)` → `"1,234,567"` | अंक-समूहन |
| `संख्या_प्रारूप(द, स्थान)` `प्रतिशत(अंश, स्थान)` | दशमलव-स्थान (⚠️ `दशमलव`-typed तर्क दो) |
| `हेक्स` `द्विआधारी` `अष्टक` `आधार_में(न,आधार)` `आधार_से(पाठ,आधार)` | आधार 2–16 रूपांतरण |
| `तालिका_पंक्ति(कक्ष, चौड़ाई)` | सरल तालिका-पंक्ति |

## जेसन.सूत्र — JSON बनाना / पार्स करना

```sutra
जेसन_बनाओ({"अंक": [१, २, ३]})      // {"अंक":[१,२,३]}   (कुंजियाँ क्रमबद्ध)
जेसन_सुंदर(म)                       // indented रूप
जेसन_पार्स("{\"क\": [true, null]}") // शब्दकोश {क: सूची [सत्य, शून्यम्]}
```
⚠️ native: बूल/दशमलव मान जब `मान`-सीमा पार करके `जेसन_बनाओ` में पहुँचें
(सूची/शब्दकोश-तत्व) तो संख्या जैसे छप सकते (tagged मान नहीं)। पार्स सही है;
पार्स किए दशमलव को उपयोग से पहले `दशमलव`-typed चर में बाँधो।

## सीएसवी.सूत्र — CSV पार्स / बनाओ (RFC 4180)

उद्धृत क्षेत्र `"..."` में `,` `\n` `"` (जोड़ी `""` से) संभालता; CRLF/LF दोनों;
अंतिम पंक्ति बिना newline भी; पूर्णतः-खाली अंतिम पंक्ति छोड़ी जाती। सब
क्षेत्र **पाठ** लौटते (संख्या-रूपांतरण caller करे)।

```sutra
सीएसवी_पार्स("नाम,आयु\nराम,30\n\"श्याम, जू\",25")
// [["नाम","आयु"], ["राम","30"], ["श्याम, जू","25"]]
सीएसवी_शब्दकोश_पार्स("नाम,आयु\nराम,30")   // [{नाम:"राम", आयु:"30"}]
सीएसवी_बनाओ([["अ","ब"], ["1","2,3"]])      // "अ,ब\r\n1,\"2,3\"\r\n"
```

| कार्य | काम |
|---|---|
| `सीएसवी_पार्स(स)` | → `सूची<सूची<पाठ>>` (पंक्तियाँ × क्षेत्र) |
| `सीएसवी_शब्दकोश_पार्स(स)` | पहली पंक्ति = हेडर → `सूची<शब्दकोश>` (कम क्षेत्र → `""`) |
| `सीएसवी_बनाओ(पंक्तियाँ)` | → पाठ (`\r\n` अंत; ज़रूरत पर क्षेत्र उद्धृत) |
| `सीएसवी_शब्दकोश_बनाओ(रो_सूची, हेडर)` | हेडर-क्रम में हर रो |
| `..._सीमांकक(..., "\t")` | हर कार्य का सीमांकक-विकल्प रूप (TSV, `;` आदि — एक अक्षर) |

## क्रमचय.सूत्र — क्रमचय / संचय / गुणन (itertools-सम)

| कार्य | काम |
|---|---|
| `क्रमचय(स)` `क्रमचय_र(स, र)` | सारे / लंबाई-र क्रमचय |
| `संचय(स, र)` | लंबाई-र संचय (क्रम-निरपेक्ष) |
| `घात_समुच्चय(स)` | सारे उपसमुच्चय (2ⁿ) |
| `कार्तीय_गुणन([[..],[..]])` | Cartesian product |
| `विंडो(स, आकार)` `लगातार_जोड़े(स)` | sliding windows / pairwise |
| `गिनती_सहित(स)` | `[[0,x0],[1,x1],...]` (enumerate) |

## ढेर_प्राथमिकता.सूत्र — न्यून-ढेर (priority queue)

```sutra
मान प = नवीन ढेर_प्राथमिकता();
प.डालो(५); प.डालो(१); प.डालो(३);
प.शिखर()     // १  (सबसे छोटा; हटता नहीं)
प.निकालो()   // १  (हट जाता है)
```
मुक्त: `ढेर_क्रम(सूची)` → heap-sort (आरोही)।

## परीक्षण.सूत्र — छोटा परीक्षण-ढाँचा

```sutra
आयात "पुस्तकालय/परीक्षण.सूत्र";
कार्य मुख्य() {
    परीक्षण_समूह("अंकगणित");
    जाँच("जोड़", २ + ३, ५);              // गहरी समानता (सूची भी)
    जाँच_सत्य("नाम", शर्त);
    जाँच_निकट("भाग", १०.०/३.०, ३.३३३, ०.०१);
    परत् परीक्षण_सारांश();               // ० = सब पास, १ = कोई विफल
}
```

## पथ.सूत्र — फ़ाइल-पथ हेरफेर (शुद्ध पाठ)

| कार्य | काम |
|---|---|
| `पथ_जोड़ो(["a","b","c.txt"])` → `"a/b/c.txt"` | टुकड़े जोड़ो |
| `आधार_नाम(प)` `निर्देशिका(प)` | basename / dirname |
| `विस्तार(प)` `मूल_नाम(प)` | extension / stem (विस्तार-रहित नाम) |
| `पथ_सामान्य(प)` | `.` / `..` सुलझाओ |
| `निरपेक्ष_है(प)` | `/` या `C:` से शुरू? |
| `साथ_विस्तार(प, "md")` | विस्तार बदलो |
| `पथ_खंड(प)` | विभाजक पर टुकड़े |

दोनों `/` और `\` इनपुट में समझे जाते; आउटपुट `/` देता। कोई फ़ाइल-तंत्र नहीं छूता।

## तर्क.सूत्र — कमांड-लाइन तर्क विश्लेषक (argparse-सम)

```sutra
आयात "पुस्तकालय/तर्क.सूत्र";
// विधि-कॉल native में receiver के static वर्ग से हल होते — इसलिए विन्यास
// को class-typed param वाले helper में रखो, और विश्लेषक `मान v = नवीन ...` से।
कार्य विन्यास(तर्क_विश्लेषक प) {
    प.ध्वज("verbose", "v");              // --verbose / -v   (बूल)
    प.विकल्प("output", "o", "a.out");    // --output x / -o x / --output=x
    प.स्थानिक("इनपुट");                  // पहला गैर-ध्वज तर्क
    परत् ०;
}
कार्य मुख्य() {
    मान प = नवीन तर्क_विश्लेषक("मेरा उपकरण");
    विन्यास(प);
    मान परिणाम = प.विश्लेषण(कार्यक्रम_तर्क());   // तर्काः() − कार्यक्रम-नाम
    यदि (परिणाम["verbose"]) { लिखतु("वाचाल"); }
    लिखतु(परिणाम["output"]);
    लिखतु(परिणाम["इनपुट"]);
    // अज्ञात/अतिरिक्त: परिणाम["_शेष"] (सूची)।  प.सहायता() → usage पाठ
}
```
समर्थित: `--लंबा`, `-छ`, `--लंबा=मान`, `-छ मान`, `--` (शेष सब positional)।
संयुक्त छोटे ध्वज (`-abc`) नहीं।

## तिथि.सूत्र — तिथि / समय (शुद्ध कैलेंडर-गणित, UTC)

एक **"पल" = 1970-01-01T00:00:00 UTC से बीते सेकंड** (i64, Unix युग)।
जोड़/घटाव/तुलना सीधे पूर्णांक; सिविल-कैलेंडर रूपांतरण Howard Hinnant के
branch-रहित सूत्रों से (Gregorian, ऋणात्मक वर्ष भी)।

```sutra
आयात "पुस्तकालय/तिथि.सूत्र";
संख्या प = समय_बनाओ(२०२६, ९, १०, १४, ३०, ०);
आईएसओ(प)                        // "2026-09-10T14:30:00Z"
तिथि_प्रारूप(प, "DD/MM/YYYY")   // "10/09/2026"
सप्ताह_दिन_नाम(प)               // "गुरुवार"
दिन_का(जोड़_माह(तिथि_बनाओ(२०२६,१,३१), १))   // २८  (माह-अंत तक clamp)
अंतर_दिन(तिथि_बनाओ(२०२६,१,१५), तिथि_बनाओ(२०२६,२,१५))   // ३१
तिथि_पार्स("2026-09-10T14:30")  // पल (या -१ गलत आकार पर)
```

| कार्य | काम |
|---|---|
| `तिथि_बनाओ(व, मा, दि)` · `समय_बनाओ(व, मा, दि, घं, मि, से)` | निर्माण (आधी-रात / पूर्ण) |
| `तिथि_अंश(प)` | `{वर्ष, माह, दिन, घंटा, मिनट, सेकंड, सप्ताह_दिन, वर्ष_दिन}` |
| `वर्ष_का` `माह_का` `दिन_का` `घंटा_का` `मिनट_का` `सेकंड_का` | एकल घटक |
| `सप्ताह_दिन(प)` | 0=रविवार .. 6=शनिवार · `वर्ष_दिन(प)` 1..366 · `दिन_आरंभ(प)` उस दिन की आधी-रात |
| `लीप_वर्ष(व)` · `माह_के_दिन(व, मा)` | 28..31 |
| `जोड़_सेकंड/मिनट/घंटा/दिन/सप्ताह(प, न)` | नियत-अवधि जोड़ |
| `जोड़_माह(प, न)` · `जोड़_वर्ष(प, न)` | कैलेंडर-सजग (दिन को माह-अंत तक clamp) |
| `अंतर_सेकंड/मिनट/घंटा/दिन(अ, ब)` | ब − अ |
| `तिथि_पूर्व` `तिथि_बाद` `तिथि_समान` `एक_दिन(अ, ब)` | तुलना |
| `माह_नाम` `माह_संक्षेप(मा)` · `सप्ताह_दिन_नाम` `सप्ताह_दिन_संक्षेप(प)` | हिंदी नाम / अंग्रेज़ी संक्षेप |
| `तिथि_प्रारूप(प, रूप)` | टोकन: `YYYY YY MM M DD D HH H mm m ss s DDD MMM MMMM ddd dddd`, बाकी अक्षर ज्यों-के-त्यों |
| `आईएसओ(प)` · `आईएसओ_तिथि(प)` | ISO 8601 |
| `तिथि_पार्स(स)` | `"YYYY-MM-DD"` / `"YYYY-MM-DDटHH:MM[:SS]"` (T या space, अंत में Z वैकल्पिक) → पल, गलत → −1 |

**सीमाएँ (v1):** केवल UTC — timezone/DST नहीं। leap-सेकंड नहीं। **"अभी"
का समय** OS-syscall/FFI है, इस शुद्ध मॉड्यूल में नहीं — caller बाहर से दे।

परीक्षण: `भाषा_परीक्षण/stdlib/तिथि_परीक्षण.सूत्र` (74 जाँच, तीनों backend)।

## यूआई.सूत्र — शुद्ध-सूत्र UI मॉडल (retained-mode)

विजेट-वृक्ष (शब्दकोश-नोड) + flexbox-उपसमुच्चय लेआउट-इंजन + चित्रण-आदेश-सूची
+ घटना-प्रेषण। **कोई pixel यहाँ नहीं खिंचता** — पुस्तकालय renderer-निरपेक्ष है;
`चित्र_सूची()` एक सपाट आदेश-सूची देता जिसे कोई भी backend (Win32 GDI,
HTML canvas, framebuffer, SVG, टर्मिनल) खींच सकता।

```sutra
आयात "पुस्तकालय/यूआई.सूत्र";

कार्य दृश्य() {
    परत् डिब्बा({"दिशा":"स्तंभ","पैडिंग":१२,"अंतर":८,"पृष्ठ_रंग":"#0f172a"}, [
        लेख("नमस्ते सूत्र", {"पाठ_आकार":१८}),
        डिब्बा({"दिशा":"पंक्ति","अंतर":८}, [
            बटन("सहेजो", "क्रिया_सहेजो", {}),
            बटन("रद्द",  "क्रिया_रद्द",  {}),
            रिक्ति(१)
        ])
    ]);
}

कार्य मुख्य() {
    शब्दकोश अवस्था = यूआई_अवस्था_नई();
    शब्दकोश जड़ = दृश्य();
    सूची आदेश = यूआई_चौखटा(जड़, अवस्था, ६४०, ४८०);  // लेआउट + चित्रण
    // आदेश → अपने renderer को दो

    शब्दकोश फल = घटना_भेजो(जड़, अवस्था, माउस_घटना("छोड़", ३०, २०));
    सूची संदेश = फल["संदेश"];   // ["क्रिया_सहेजो"] जैसे id — App खुद dispatch करे
}
```

**विजेट:** `डिब्बा(गुण, बच्चे)` · `लेख(सामग्री, गुण)` · `बटन(सामग्री, क्रिया, गुण)`
· `रिक्ति(बढ़त)` (लचीली खाली जगह)

**गुण** (सब वैकल्पिक): `दिशा` `"स्तंभ"`(default)/`"पंक्ति"` · `अंतर` (gap) · `पैडिंग`
· `चौड़ाई`/`ऊँचाई` (नियत) · `बढ़त` (flex-grow भार) · `संरेखण` `"तनाव"`(default)/
`"आरंभ"`/`"मध्य"`/`"अंत"` · `पृष्ठ_रंग` `किनारा_रंग` `किनारा_मोटाई` `कोना` ·
`पाठ_रंग` `पाठ_आकार` `पाठ_संरेखण` · बटन: `क्रिया` (click पर उत्सर्जित id),
`होवर_रंग` `दबा_रंग` `अक्षम`

**कार्य:**

| कार्य | काम |
|---|---|
| `लेआउट_करो(जड़, चौड़ाई, ऊँचाई)` | दो-पास flexbox — हर नोड में `"स्थान"` (बाएँ/ऊपर/चौड़ाई/ऊँचाई) भरता |
| `चित्र_सूची(जड़, अवस्था)` | सपाट आदेश-सूची: `{आदेश:"आयत"/"पाठ"/"किनारा", ...}` |
| `यूआई_चौखटा(जड़, अवस्था, चौ, ऊँ)` | लेआउट + चित्रण एक साथ |
| `यूआई_अवस्था_नई()` | `{होवर, दबा, केंद्रित}` — frames के बीच retained interaction-अवस्था |
| `माउस_घटना("गति"/"दबाव"/"छोड़", क्ष, य)` | घटना-रिकॉर्ड |
| `घटना_भेजो(जड़, अवस्था, घटना)` | hit-test + अवस्था अद्यतन → `{अवस्था, संदेश:[id...]}` (click पर) |
| `यूआई_खोजो_क्रिया(जड़, क्रिया)` | क्रिया-id से नोड (गहराई-प्रथम) |
| `यूआई_बाहर_गया(अवस्था)` | माउस दायरे-बाहर → hover/press साफ़ |

**घटना-मॉडल:** प्रथम-श्रेणी कार्य नहीं तो callbacks नहीं — `घटना_भेजो` संदेश-id
की सूची लौटाता (Elm-शैली); App अपना state रखे, `दृश्य()` से वृक्ष दुबारा बनाए,
messages पर `यदि id == "..."` से dispatch करे। Interaction-अवस्था (hover/press)
अलग `अवस्था` शब्दकोश में retained रहती चाहे वृक्ष हर frame नया बने।

पाठ-चौड़ाई मोटा estimate है (`यूआई_पाठ_चौड़ाई`) — सटीकता चाहिए तो नियत `चौड़ाई`
गुण दो, या renderer से माप वापस दो। निर्देशांक पूर्णांक (px)।

देखो: `उदाहरण/यूआई_झलक.सूत्र`, परीक्षण `भाषा_परीक्षण/stdlib/यूआई_परीक्षण.सूत्र` (30 जाँच)।

## व्यंजक.सूत्र — नियमित अभिव्यक्ति (regular expressions)

```sutra
आयात "पुस्तकालय/व्यंजक.सूत्र";
व्यंजक_मिलान("[0-9]+", "अंक 42 यहाँ")        // सत्य
व्यंजक_खोजो("\\d+", "क3म14")                  // {मिला:सत्य, आरंभ:१, अंत:२, पाठ:"3", समूह:[]}
व्यंजक_सभी_खोजो("\\d+", "क3म14ल5")            // ["3", "14", "5"]
व्यंजक_बदलो("[aeiou]", "hello", "*")          // "h*ll*"
व्यंजक_विभाजित(",\\s*", "अ, ब,ग")             // ["अ", "ब", "ग"]

// capturing groups
शब्दकोश मि = व्यंजक_खोजो("(\\d+)-(\\d+)", "12-34");
व्यंजक_समूह(मि, १)   // "12"
व्यंजक_समूह(मि, २)   // "34"
व्यंजक_सभी_खोजो_विस्तृत("(\\w)=(\\d)", "a=1,b=2")   // हर मिलान का पूरा विवरण

// नामित capturing groups — (?<नाम>...), \k<नाम>
शब्दकोश ना_मि = व्यंजक_खोजो("(?<वर्ष>\\d{4})-(?<माह>\\d{2})-(?<दिन>\\d{2})", "2026-09-14");
व्यंजक_समूह_नाम(ना_मि, "वर्ष")   // "2026" — व्यंजक_समूह(ना_मि, १) से भी वही
व्यंजक_मिलान("(?<श>\\w+)\\s+\\k<श>", "hello hello")   // सत्य — नामित backreference

// {n,m} गिनती-दोहराव
व्यंजक_मिलान("\\d{3}-\\d{4}", "फ़ोन: 123-4567")   // सत्य
व्यंजक_पूर्ण_मिलान("a{2,4}", "aaa")               // सत्य

// backreference
व्यंजक_पूर्ण_मिलान("(\\w+)\\s+\\1", "hello hello")   // सत्य — दोहराया शब्द
व्यंजक_बदलो("(\\w+)@(\\w+)", "user@host", "$2@$1")    // "host@user"

// lookahead/lookbehind
व्यंजक_खोजो("\\d+(?=px)", "10px")["पाठ"]              // "10" (px उपभोग नहीं)
व्यंजक_मिलान("(?<=\\$)\\d+", "$100")                  // सत्य
व्यंजक_मिलान("^(?=.*[A-Z])(?=.*\\d).{8,}$", "Abc12345") // सत्य — पासवर्ड-जैसा
```

समर्थित: literal, `.`, `*`/`+`/`?` (greedy), `{n}`/`{n,}`/`{n,m}` (greedy
गिनती-दोहराव), `[abc]`/`[^abc]`/`[a-z]`, `^`/`$`, `|`, `(...)` **पकड़ने वाला
समूह (capturing group)**, `(?<नाम>...)` **नामित समूह**, `(?:...)` न-पकड़ने
वाला समूह, `(?=...)`/`(?!...)` **आगे-दृष्टि (lookahead)**, `(?<=...)`/
`(?<!...)` **पीछे-दृष्टि (lookbehind, स्थिर-लंबाई)**, `\d \D \w \W \s \S`,
`\1`-`\9` **backreference** (पैटर्न में), `\k<नाम>` **नामित backreference**,
`\`-escape। तरीका: पैटर्न को Thompson-शैली bytecode (अक्षर/वर्ग/कूद/
विभाजन/मिलान/**पकड़_आरंभ/पकड़_अंत/पीछे_संदर्भ/आगे_दृष्टि/पीछे_दृष्टि**) में
संकलित करके recursive backtracking VM से चलाया — कूद/विभाजन के लक्ष्य
संख्या-सूचकांक हैं, closure नहीं (Sutra में प्रथम-श्रेणी फलन नहीं)।

**Lookahead/lookbehind (2026-09-14 जोड़े):** दोनों शून्य-चौड़ाई दावे — मिलते
हैं (या नहीं मिलते) पर पाठ *उपभोग नहीं* करते। `(?=X)`/`(?!X)` (lookahead)
आगे की ओर जाँचते — X किसी भी लंबाई का हो सकता (VM पहले से backtracking है,
कोई अतिरिक्त सीमा नहीं); सफल सकारात्मक lookahead के भीतर capturing groups
बाहर भी उजागर रहते (`(?=(\d+))` से समूह-1 आगे इस्तेमाल हो सकता)। `(?<=X)`/
`(?<!X)` (lookbehind) पीछे की ओर जाँचते — X की लंबाई **संकलन-समय पर स्थिर**
होनी ज़रूरी (कोई `*`/`+`/`{n,m}` जहाँ n≠m, कोई `\N` भीतर नहीं — दोनों compile-
time त्रुटि देते) — ज़्यादातर प्रमुख regex engine (Perl/PCRE/RE2/Rust) भी यही
सीमा रखते हैं, यह कोई मनमानी कमी नहीं। नकारात्मक रूपों ((?!X)/(?<!X)) के
capture कभी उजागर नहीं होते। दोनों नेस्टेड हो सकते और capturing groups के
साथ मिलकर काम करते।

**Backreference (2026-09-14 जोड़े):** पैटर्न में `\1`-`\9` वही *पाठ* माँगता
है जो उस समूह ने रन-टाइम पर पकड़ा (सिर्फ़ वही उप-पैटर्न दोबारा नहीं) — जैसे
`(\w+)\s+\1` दोहराया शब्द पकड़ता। समूह अभी तक न मिला हो तो `\N` असफल होता
(शून्य-चौड़ाई-मिलान के बजाय)। कई backreference (`(\w)(\w)\2\1` जैसे
palindrome-पैटर्न) और दोहराए समूह पर backreference (अंतिम पुनरावृत्ति का
मान) दोनों काम करते। संकलन-समय पर सत्यापित — किसी अघोषित समूह का `\N`
compile-time त्रुटि देता, runtime हमेशा-असफल छिपने के बजाय। अलग से,
`व्यंजक_बदलो` के प्रतिस्थापन-पाठ में `$1`-`$9` (समूह का पाठ), `$0` (पूरा
मिलान), `$$` (literal `$`) — पैटर्न-backreference (`\N`) से स्वतंत्र
तंत्र, बिना `$` वाला प्रतिस्थापन पहले जैसा बिल्कुल अपरिवर्तित।

**`{n,m}` गिनती-दोहराव (2026-09-14 जोड़े):** नया bytecode नहीं — `A{n,m}` = n
अनिवार्य प्रतियाँ `A` + (m−n) वैकल्पिक (`?`) प्रतियाँ क्रम में (greedy);
`A{n,}` = n अनिवार्य + एक `*` पूंछ; `A{n}` = सिर्फ़ n अनिवार्य प्रतियाँ। तीनों
पहले से मौजूद व मान्य `*`/`+`/`?` bytecode-रास्तों में विघटित होते — मूल तीन
हाथ-अनुकूलित रास्ते अपरिवर्तित रहे, सिर्फ़ एक नया सामान्य decomposition-केस
जोड़ा। `m < n` या टूटा हुआ `{...}` (गुम अंक/`}`) compile-time त्रुटि देते
(`प्रयत्न`/`पकड़ो` से पकड़ने-योग्य)। Capturing groups के साथ भी काम करता
(`(\d{2,4})` जैसे पैटर्न)।

**Capturing groups (2026-09-13 जोड़े):** `व्यंजक_खोजो`/`व्यंजक_सभी_खोजो_विस्तृत`
के परिणाम में `"समूह"` = सूची (index 0 = समूह 1 का पाठ, आदि — न मिले तो
`शून्यम्`)। `व्यंजक_समूह(परिणाम, क्रमांक)` से 1-आधारित सुविधाजनक पहुँच।
समूह-क्रमांक बाएँ-से-दाएँ खुलते कोष्ठक के क्रम में (नेस्टेड समूह सहित) —
मानक regex परंपरा जैसा। दोहराए गए समूह (`(a)+` जैसे) की अंतिम पुनरावृत्ति
का मान रिपोर्ट होता। कैप्चर-अवस्था backtracking-सुरक्षित है — `विभाजन`
(split) की पहली शाखा आंशिक रूप से capture सेट करके असफल हो तो दूसरी शाखा
आज़माने से पहले वह capture वापस अपनी पुरानी अवस्था में लौटता (snapshot/
restore), ताकि असफल शाखा के stale capture सफल शाखा के परिणाम में न रिसें
— विकल्प (`|`) के साथ capturing groups का सबसे नाज़ुक हिस्सा, परीक्षण में
विशेष रूप से जाँचा गया (नेस्टेड मामलों समेत)। `व्यंजक_सभी_खोजो`/
`व्यंजक_बदलो`/`व्यंजक_विभाजित` पहले जैसे अपरिवर्तित (सिर्फ़ पाठ, capture
से अप्रभावित) — पूरे मिलान-विवरण (capture सहित) के लिए `व्यंजक_खोजो` या
नया `व्यंजक_सभी_खोजो_विस्तृत` इस्तेमाल करो।

**नामित Capturing groups (2026-09-14 जोड़े):** `(?<नाम>X)` एक सामान्य
capturing group ही है (क्रमांक भी मिलता, ऊपर जैसा बाएँ-से-दाएँ), बस उसे
`व्यंजक_समूह_नाम(परिणाम, "नाम")` से नाम द्वारा भी पाया जा सकता (अज्ञात नाम
→ `शून्यम्`, त्रुटि नहीं)। दो समूहों को एक ही नाम देना compile-time त्रुटि।
नाम में `>` के अलावा कुछ भी चल सकता (Devanagari या ASCII दोनों) — यह सूत्र
का अपना पहचानकर्ता नहीं, सिर्फ़ पैटर्न-पाठ के भीतर एक लेबल-स्ट्रिंग है।
`\k<नाम>` नामित backreference है — `\N` जैसा ही runtime-व्यवहार, बस नाम से
संदर्भित; नाम `\k` से *पहले* पार्स हो चुके किसी घोषित समूह को ही संदर्भित
कर सकता (आगे वाले को नहीं — सामान्य forward-reference समर्थित नहीं, ज़्यादातर
व्यावहारिक पैटर्न में यही चाहिए भी होता)। lookahead/lookbehind के भीतर
घोषित नामित समूह भी बाहर उजागर होते, बिल्कुल अनामित समूहों जैसा।

⚠️ अगर कोई `*`/`+`/`{n,}` से दोहराया भाग खाली-पाठ पर भी मिल सकता है (`(a?)*`
जैसा), engine अनंत-लूप में फँस सकता — व्यावहारिक पैटर्न में यह शायद ही आता।

देखो: `भाषा_परीक्षण/stdlib/व्यंजक_परीक्षण.सूत्र` (155 जाँच — मूल 64 + 31 capturing-
groups + 20 `{n,m}` + 13 backreference + 14 lookahead/lookbehind (incl.
कई-lookahead पासवर्ड-सत्यापन-जैसा पैटर्न + दोनों lookbehind-सीमा त्रुटियाँ)
+ 13 नामित समूह/backreference — **x86 + interpreter + `--release` तीनों पर
155/155**, कोई regression नहीं)।

## एसएचए256.सूत्र — SHA-256 क्रिप्टोग्राफ़िक हैश (FIPS 180-4)

```sutra
आयात "पुस्तकालय/एसएचए256.सूत्र";
एसएचए256_हैश("")     // "e3b0c44298fc1c149afbf4c8996fb92427ae41e4649b934ca495991b7852b85"[६४]
एसएचए256_हैश("abc")  // "ba7816bf8f01cfea414140de5dae2223b00361a396177a9cb410ff61f20015ad"[६४]
```

FIPS 180-4 का प्रकाशित गणित-विनिर्देश सीधे लागू — इसमें कोई डिज़ाइन-
स्वतंत्रता नहीं (हर संक्रिया मानक तय करता), बस किसी और की source-code
कॉपी/अनुवाद नहीं की। पाठ को पहले शुद्ध-Sutra UTF-8 encoder से बाइट्स में
बदला जाता (Sutra का `उपखंड`/`लंबाई` codepoint-स्तर पर है, byte-स्तर पर
नहीं — इसलिए बहु-बाइट पाठ को हैश करने के लिए खुद encode करना ज़रूरी, नहीं
तो `sha256sum` से मेल न खाता)। 32-बिट गणित 64-बिट `संख्या` पर हर जोड़/
rotate के बाद निचले 32 बिट पर मास्क करके। कई मानक-स्थिरांक (H₀..H₇,
K₀..K₆₃) 2³¹ से बड़े हैं (literal-सीमा से बाहर) — hi16/lo16 जोड़ों से बनाए।
सत्यापन .NET के `System.Security.Cryptography.SHA256` से generate किए
test-vectors से — किसी की याददाश्त से नहीं।

देखो: `भाषा_परीक्षण/stdlib/एसएचए256_परीक्षण.सूत्र` (13 जाँच — मानक vectors,
ब्लॉक-सीमा edge cases 55/56/64/65 बाइट, बहु-बाइट UTF-8, गुण — x86 +
interpreter दोनों पास)।

## संकुचन.सूत्र — LZ77-शैली संपीड़न (compression)

```sutra
आयात "पुस्तकालय/संकुचन.सूत्र";
सूची क = संकुचन_पाठ_संपीड़ित("अ अ अ अ अ अ अ अ अ अ");
पाठ वापस = संकुचन_पाठ_विसंपीड़ित(क);       // मूल पाठ वापस

सूची कच्चा = संकुचन_संपीड़ित([१,१,१,१,१,१,१,१,१,१]);   // कच्चे बाइट्स पर सीधे
संकुचन_विसंपीड़ित(कच्चा)
```

मौलिक डिज़ाइन — DEFLATE/gzip का bitstream-प्रारूप कॉपी नहीं किया, LZ77 का
सामान्य *सिद्धांत* (पीछे दोहराया भाग दूरी+लंबाई से संदर्भित करना) समझ के
अपना byte-aligned टोकन-प्रारूप बनाया: हर टोकन `[0][बाइट]` (literal) या
`[1][दूरी_उच्च][दूरी_निम्न][लंबाई]` (पीछे-संदर्भ)। कोई bit-packing/Huffman
नहीं (v1) — इसलिए gzip जितना संकुचित नहीं होता, पर दोहराव वाले डेटा पर
वास्तविक, सही संकुचन देता है। Overlapping self-reference (जैसे "aaaa" या
"ababab") सही चलता — byte-दर-byte कॉपी होती तो हाल ही लिखा बाइट खुद अगले
का स्रोत बन सकता। खिड़की 4096 बाइट, न्यूनतम-मैच 3, अधिकतम-मैच 255; मैच-
खोज naive O(n×खिड़की) है (गति नहीं, शुद्धता प्राथमिकता — बड़े इनपुट पर
भविष्य में बेहतर खोज जोड़ी जा सकती)। पाठ के लिए UTF-8 एन्कोड/डिकोड शामिल
(Sutra का उपखंड/लंबाई codepoint-स्तर पर है, byte-स्तर पर नहीं)।

देखो: `भाषा_परीक्षण/stdlib/संकुचन_परीक्षण.सूत्र` (13 जाँच — गोल-यात्रा, overlapping
self-reference, खिड़की-सीमा से बड़ा इनपुट, असली संकुचन-अनुपात, कच्चे बाइट्स।
x86 + interpreter दोनों पास)।

## यादृच्छिक.सूत्र — उच्च-गुणवत्ता PRNG (xorshift128, बहु-धारा)

```sutra
आयात "पुस्तकालय/यादृच्छिक.सूत्र";
शब्दकोश रा = यादृ_बनाओ(४२);          // स्थिर बीज — नियतात्मक, दोहराई-योग्य धारा
संख्या न = यादृ_परास(रा, १, ६);      // पासा फेंक (१..६ सम्मिलित)
दशमलव द = यादृ_दशमलव(रा);            // [०,१) दशमलव
सूची फ = यादृ_फेंटो(रा, [१,२,३,४]);  // फ़िशर-येट्स फेंटना, नई सूची
```

`गणित.सूत्र` में पहले से एक बुनियादी PRNG है (`यादृच्छिक_बीज`/`यादृच्छिक_अगला` —
MINSTD/Park-Miller LCG, एकल global धारा) — यह मॉड्यूल उसकी जगह नहीं लेता, दो
असली सुधार जोड़ता है: (1) **गुणवत्ता** — Marsaglia की xorshift128 (शुद्ध
shift+xor, कोई गुणा नहीं, 128-बिट अवस्था) — सार्वजनिक/अकादमिक एल्गोरिथ्म
(SHA-256 का FIPS स्पेक जैसा — समझ के अपना कार्यान्वयन, कॉपी नहीं), LCG के
जाने-पहचाने निम्न-बिट सहसंबंध यहाँ नहीं होते; (2) **बहु-धारा** — अवस्था एक
शब्दकोश में रहती है (संदर्भ द्वारा उत्परिवर्तित), तो कई स्वतंत्र, एक-दूसरे से
अप्रभावित यादृच्छिक धाराएँ एक साथ बनाई जा सकती हैं। आंतरिक रूप से बीज-विस्तार
के लिए गणित.सूत्र के मौजूदा LCG का पुनःप्रयोग करता है (⚠ इसलिए `यादृ_बनाओ`
गणित.सूत्र के global बीज को अस्थायी रूप से बदलता है — विवरण फ़ाइल-हेडर में)।
पूरी तरह शुद्ध Sutra, कोई FFI/OS निर्भरता नहीं — तीनों बैकएंड पर समान चलता है,
जानबूझकर कोई auto-seed नहीं (नियतात्मक-दर-डिफ़ॉल्ट)।

देखो: `भाषा_परीक्षण/stdlib/यादृच्छिक_परीक्षण.सूत्र` (सटीक संदर्भ मान — PowerShell में
दो स्वतंत्र तरीकों से क्रॉस-चेक करके निकाले, सिर्फ़ property-आधारित नहीं —
यादृच्छिक_परीक्षण/एसएचए256_परीक्षण जैसी rigor — + नियतात्मकता, स्वतंत्र-धारा,
परास/फेंटो/तत्व-चुनाव, गणित.सूत्र सह-अस्तित्व। x86 + `--release` दोनों पास)।

⚠ **इस मॉड्यूल को बनाते वक़्त एक असली कम्पाइलर-बग मिला** (अलग से track किया,
अभी fix नहीं किया — देखो `project_sutra_language.md`): जब एक संख्या-वापस-
करने-वाले फलन का कॉल *सीधे* एक मिश्रित संख्या/दशमलव अभिव्यक्ति के अंदर
इस्तेमाल होता है (जैसे `(फलन() * 1.0) / भाजक`), तो दशमलव-प्रकार-अनुमान ग़लत
हो जाता है और परिणाम ग़लत होता है (कच्चा संख्या मान लौटता है, ठीक से भाग हुआ
दशमलव नहीं)। वर्कअराउंड: फलन-कॉल के परिणाम को *पहले* एक अलग `संख्या` स्थानीय
चर में रखो, *फिर* उसे मिश्रित अभिव्यक्ति में इस्तेमाल करो — `यादृ_दशमलव` में
लागू है, कोड-टिप्पणी सहित।

## बेस64.सूत्र — Base64 एन्कोडिंग/डिकोडिंग (RFC 4648)

```sutra
आयात "पुस्तकालय/बेस64.सूत्र";
पाठ ए = बेस64_एन्कोड([७२, १०१, १०८, १०८, १११]);   // "SGVsbG8="
सूची बा = बेस64_डिकोड(ए);                          // [७२,१०१,१०८,१०८,१११]

पाठ ए2 = बेस64_पाठ_एन्कोड("नमस्ते");   // UTF-8 एन्कोड + Base64 एन्कोड
पाठ वापस = बेस64_पाठ_डिकोड(ए2);        // "नमस्ते"
```

मानक RFC 4648 बिट-पैकिंग — SHA-256 के FIPS स्पेक जैसा सार्वजनिक गणितीय स्पेक,
कॉपी नहीं, सीधे लिखा। हर 3 बाइट (24 बिट) → चार 6-बिट टुकड़े → वर्णमाला
`A-Za-z0-9+/` में 4 अक्षर; बाकी बचे 1/2 बाइट पर `=` पैडिंग। अक्षर→मान
रूपांतरण दिक्शनरी-लुकअप की जगह सीधे ASCII-श्रेणी अंकगणित से (तेज़, सरल)।
पाठ-सुविधा फलन UTF-8 एन्कोड/डिकोड के लिए संकुचन.सूत्र का पुनःप्रयोग करते हैं।
v1: सख़्त डिकोडर — इनपुट की लंबाई 4 का गुणज मानी जाती है, बीच में
व्हाइटस्पेस/लाइन-रैप (MIME-शैली) समर्थित नहीं।

देखो: `भाषा_परीक्षण/stdlib/बेस64_परीक्षण.सूत्र` (34 जाँच — RFC 4648 के क्लासिक
"f"/"fo"/"foo"/.../"foobar" संदर्भ सदिश + बहु-बाइट देवनागरी + पूरी वर्णमाला
(+ और / सहित) कच्चे बाइट्स + गोल-यात्रा सारी लंबाई-श्रेणियों पर — सारे संदर्भ
मान PowerShell के `[Convert]::ToBase64String` से क्रॉस-चेक किए, सिर्फ़
round-trip नहीं। **x86 + interpreter + `--release` तीनों बैकएंड पर 34/34
पास।**)

## यूआईडी.सूत्र — UUID संस्करण ४ (RFC 4122)

```sutra
आयात "पुस्तकालय/यूआईडी.सूत्र";
शब्दकोश रा = यादृ_बनाओ(४२);              // यादृच्छिक.सूत्र से — कोई भी बीज
पाठ आ = यूआईडी_संस्करण४(रा);              // "a1b2c3d4-e5f6-4789-a123-456789abcdef"
यूआईडी_मान्य_है(आ)                        // सत्य
यूआईडी_रिक्त()                            // "00000000-0000-0000-0000-000000000000"
```

RFC 4122 §4.4 का सटीक एल्गोरिथ्म — 128 यादृच्छिक बिट (यादृच्छिक.सूत्र की
xorshift128 धारा से), फिर संस्करण-निबल (बाइट 6 का ऊपरी निबल = 4) और
variant-बिट (बाइट 8 के ऊपरी 2 बिट = 10) ओवरराइट — मानक 8-4-4-4-12
hex-प्रारूप में। `यूआईडी_मान्य_है` आकार/हाइफ़न-स्थिति/hex-अंक जाँचता
(case-insensitive), संस्करण-विशिष्ट नहीं — कोई भी वैध-दिखने वाला UUID
मान्य गिनता। `यूआईडी_रिक्त()` RFC का "nil UUID" (सर्व-शून्य) सेंटिनल है।

⚠️ **क्रिप्टोग्राफ़िक-सुरक्षित नहीं** — यादृच्छिक.सूत्र की xorshift128 PRNG
इस्तेमाल होती (कोई OS CSPRNG नहीं); session-token/गोपनीय-कुंजी के लिए मत
इस्तेमाल करो, सिर्फ़ DB-key/अनुरोध-id जैसे व्यावहारिक unique-id मामलों के

## महासंख्या.सूत्र — मनमाने आकार के पूर्णांक (arbitrary-precision integers)

```sutra
आयात "पुस्तकालय/महासंख्या.सूत्र";
शब्दकोश अ = महासंख्या_बनाओ(१२३४५);
शब्दकोश ब = महासंख्या_पाठ_से("९९९९९९९९९९९९९९९९९९९९९९९९९९९९९९९९");
पाठ स = महासंख्या_से_पाठ(महासंख्या_गुणा(अ, ब));
शब्दकोश फै = महासंख्या_गुणनखंड(५०);                      // ५०! — देशी संख्या में नहीं समाता
शब्दकोश गु = महासंख्या_घात_मॉड(अ, महासंख्या_बनाओ(१०), ब); // modular घातांक
```

देशी `संख्या` 64-बिट है, पर स्रोत-साहित्य 2³¹ से ऊपर सीधा नहीं लिखा जा
सकता — महासंख्या.सूत्र उस सीमा से परे बड़े पूर्णांकों के लिए है: गुणनखंड,
modular घातांक (RSA-शैली), संयोजिकी। आंतरिक निरूपण: चिह्न + आधार-10⁹
अंक-समूहों (limb) की सूची, little-endian। स्कूली गुणा O(n·m), द्विआधारी-
खोज वाला लंबा भाग O(n·m·log(आधार)) — सामान्य उपयोग के लिए पर्याप्त,
RSA-4096-स्तरीय प्रदर्शन का लक्ष्य नहीं।

पाठ-रूपांतरण (`महासंख्या_से_पाठ`/`महासंख्या_पाठ_से`) देवनागरी अंकों में
है — यह "हमारा अपना" निरूपण है (SHA-256 hex जैसा बाहरी मानक नहीं), इसलिए
देवनागरी नियम लागू होता है। भाग/शेष का चिह्न-नियम देशी `/`/`%` से मेल
खाता है (सत्यापित): भागफल 0 की ओर छाँटा जाता, शेष सदा भाज्य का चिह्न लेता।

पूरी API: निर्माण/रूपांतरण (`महासंख्या_बनाओ`, `महासंख्या_शून्य`,
`महासंख्या_पाठ_से`, `महासंख्या_से_पाठ`, `महासंख्या_से_संख्या`), तुलना
(`महासंख्या_तुलना`, `महासंख्या_बराबर`, `महासंख्या_शून्य_है`,
`महासंख्या_ऋणात्मक_है`, `महासंख्या_सम_है`/`महासंख्या_विषम_है`), अंकगणित
(`महासंख्या_जोड़`/`घटाओ`/`गुणा`/`ऋणात्मक`/`निरपेक्ष`,
`महासंख्या_भाग_शेष`/`भाग`/`शेष`, `महासंख्या_घात`, `महासंख्या_घात_मॉड`,
`महासंख्या_गुणनखंड`)।

⚠️ `महासंख्या_से_संख्या` सिर्फ़ तभी सफल जब |मान| < 10¹⁸ (2 अंक-समूह) —
इससे बड़ा (भले ही देशी 64-बिट `संख्या` में तकनीकी रूप से समा जाए, जैसे

के सिद्धांत पर। ⚠️ `महासंख्या_पाठ_से` सिर्फ़ देवनागरी अंक स्वीकारता — बाहरी

## यूआरएल.सूत्र — URL/URI पार्सिंग/निर्माण (RFC 3986)


## एचएमएसी.सूत्र — HMAC-SHA256 (RFC 2104 / FIPS 198-1)

```sutra
आयात "पुस्तकालय/एचएमएसी.सूत्र";
एचएमएसी_एसएचए256("key", "The quick brown fox jumps over the lazy dog")
// "f7bc83f430538424b13298e6aa6fb143ef4d59a14946175997479dbc2d1a3cd8"
```

RFC 2104: `HMAC(K,m) = H((K'⊕opad) || H((K'⊕ipad) || m))`, H = SHA-256
(ब्लॉक आकार 64 बाइट)। कुंजी 64 बाइट से लंबी हो तो पहले खुद हैश होती,
फिर दोनों स्थिति में शून्य-भरण से ठीक 64 बाइट तक। एसएचए256.सूत्र के ऊपर
बना — उसके नए सार्वजनिक `एसएचए256_हैश_बाइट्स` (कच्चे बाइट्स लेता, पाठ
नहीं — कुंजी क्रिप्टोग्राफ़िक डेटा है, ज़रूरी नहीं मान्य UTF-8 पाठ हो) का
इस्तेमाल करता; `एसएचए256_हैश` अब इसी पर एक पतला wrapper है (व्यवहार
अपरिवर्तित)।

⚠️ किसी HMAC को अपेक्षित मान से मिलाना हो (जैसे signature-verification)
तो समय-स्थिर (constant-time) तुलना से करो, साधारण `==` से नहीं — यह
मॉड्यूल सिर्फ़ गणना देता, तुलना-सुरक्षा caller की ज़िम्मेदारी है।

मान .NET के `HMACSHA256` से सीधे generate किए गए, हाथ से टाइप नहीं;

## कैश.सूत्र — LRU (Least Recently Used) कैश

```sutra
आयात "पुस्तकालय/कैश.सूत्र";
शब्दकोश क = कैश_बनाओ(२);              // क्षमता = 2
कैश_रखो(क, "अ", "1");
कैश_रखो(क, "ब", "2");
कैश_पाओ(क, "अ");                      // "1" — अ अब सबसे हाल इस्तेमाल
कैश_रखो(क, "स", "3");                 // क्षमता पूरी — ब हटाया जाता (सबसे पुराना)
कैश_है(क, "ब")                        // असत्य
कैश_है(क, "अ")                        // सत्य
```

निरूपण: दोहरी-कड़ी सूची (नोड=शब्दकोश `{"कुंजी","मूल्य","पिछला","अगला"}`)
+ एक शब्दकोश मानचित्र (कुंजी→नोड), दोनों O(1) पहुँच के लिए। API:
`कैश_बनाओ`(क्षमता), `कैश_पाओ`/`कैश_रखो` (दोनों recency ताज़ा करते),
`कैश_है` (शुद्ध peek, recency पर असर नहीं), `कैश_हटाओ`, `कैश_आकार`,
`कैश_खाली_है`, `कैश_खाली_करो`, `कैश_कुंजियाँ_क्रम_में` (MRU→LRU सूची,
डीबग/परीक्षण के लिए)। कुंजी सदा `पाठ`; मूल्य `मान` (कोई भी प्रकार)।

⚠️ **निष्कासन (eviction) O(1) नहीं, O(क्षमता) है** — मानचित्र से कुंजी
हटाने को शब्दकोश.सूत्र का `कुंजी_हटाओ` इस्तेमाल होता (अंतर्निहित
हटाएं() शब्दकोश पर native में नहीं चलता), जो पूरा मानचित्र दोबारा
बनाता। पाओ/रखो की खोज खुद (कुंजी_है + प्रत्यक्ष अनुक्रमण) अब भी O(1)
रहती। बंधी हुई स्मृति को निष्कासन-गति से ऊपर जानबूझकर चुना गया —
विकल्प (शून्यम्-चिह्नित सॉफ़्ट-डिलीट) मानचित्र को असीमित बढ़ने देता।
छोटी-मध्यम क्षमता के लिए यह व्यवहारिक रूप से कोई समस्या नहीं।

⚠️ **इस दौरान एक नया compiled-backend bug मिला**: `जोड़ें()` से किसी
फ़ंक्शन के अंदर लूप में बनी (न कि सीधे literal `[...]`) सूची, फ़ंक्शन से
लौटने के बाद `जाँच()` के `मान` पैरामीटर से तुलना करने पर native x86 और
`--release` दोनों पर ग़लत व्यवहार करती (असली सूची की जगह एक raw
handle-नंबर प्रिंट होता) — पर `लंबाई()`/अनुक्रमण से वही सूची सही ढंग से
पढ़ी जाती है, और interpreter पर सब सही। इसीलिए `कैश_कुंजियाँ_क्रम_में`
के परीक्षण हमेशा `लंबाई()` + अनुक्रमित-तत्व से तुलना करते, कभी पूरी
सूची को सीधे `जाँच()` में नहीं देते। अलग background task में दर्ज।

देखो: `भाषा_परीक्षण/stdlib/कैश_परीक्षण.सूत्र` (52 जाँच — मूल रखो/पाओ,
MRU→LRU क्रम, निष्कासन, recency (पाओ रिफ्रेश करता, है()-peek नहीं),
मौजूदा-कुंजी अद्यतन, स्पष्ट हटाओ, खाली_करो, क्षमता-1 किनारा, अमान्य
क्षमता (0/ऋणात्मक दोनों त्रुटि), बहु-बाइट UTF-8 देवनागरी + मिश्रित

## आव्यूह.सूत्र — आव्यूह (Matrix) / रैखिक बीजगणित (linear algebra)

```sutra
आयात "पुस्तकालय/आव्यूह.सूत्र";
शब्दकोश आ = आव्यूह_से_पंक्तियाँ([[1.0, 2.0], [3.0, 4.0]]);
शब्दकोश ब = आव्यूह_पहचान(२);
शब्दकोश स = आव्यूह_गुणा(आ, ब);
आव्यूह_पाओ(स, ०, १)                 // 2.0
आव्यूह_निर्धारक(आ)                  // -2.0
आव्यूह_व्युत्क्रम(आ)                 // आ का व्युत्क्रम
```

निरूपण: शब्दकोश `{"पंक्तियाँ","स्तंभ","डेटा"}` — "डेटा" एक चपटी
(flat, row-major) सूची of `दशमलव`, नेस्टेड सूची-of-सूची नहीं। API:
`आव्यूह_बनाओ`/`आव्यूह_पहचान`/`आव्यूह_से_पंक्तियाँ` (निर्माण),
`आव्यूह_पाओ`/`आव्यूह_सेट` (O(1) पहुँच, सेट जगह पर बदलता), `आव्यूह_जोड़`/
`घटाओ`/`अदिश_गुणा`/`गुणा`/`स्थानांतरण` (सभी नया आव्यूह लौटाते),
`आव्यूह_निर्धारक`/`आव्यूह_व्युत्क्रम` (recursive cofactor expansion —
गणितीय रूप से हमेशा सही, पर **O(n!) समय**, सिर्फ़ छोटे आव्यूह
(व्यवहारिक रूप से n ≤ 8-10) के लिए — LU-decomposition जानबूझकर स्कोप
से बाहर, आलेख.सूत्र के O(V²) डिज्क्स्ट्रा जैसा ही सरलता-प्राथमिकता
व्यापार), `आव्यूह_लगभग_बराबर`/`शून्य_है`/`पहचान_है`/`से_पाठ`।

   expression में) native x86 और `--release` दोनों पर दशमलव तत्व का
   raw IEEE-754 bit-pattern एक integer की तरह लौटाती (असली मान नहीं)
   — जबकि इंटरमीडिएट नामित वेरिएबल से होकर अलग-अलग single-level
   indexing (`सूची पंक्ति = अ[i]; मूल्य = पंक्ति[j];`) हमेशा सही चलता।

   सिद्ध-सुरक्षित मामला ठीक करता — *केवल* जब नेस्टेड सूची एकसमान-गहराई का

2. **ज़्यादा गंभीर**: दो `दशमलव`-लौटाने वाले फ़ंक्शन-कॉल सीधे एक ही

   पूरी तरह सही चलता — यह पूरे मॉड्यूल में हर जगह (जोड़/घटाओ/गुणा/

## क्रमित_मानचित्र.सूत्र — क्रमित मानचित्र (sorted map, AVL वृक्ष)

```sutra
आयात "पुस्तकालय/क्रमित_मानचित्र.सूत्र";
शब्दकोश म = क्रमित_बनाओ();
क्रमित_रखो(म, ३०, "ग");
क्रमित_रखो(म, १०, "क");
क्रमित_रखो(म, २०, "ख");
क्रमित_कुंजियाँ(म)              // [10, 20, 30] — हमेशा आरोही क्रम
क्रमित_पाओ(म, २०)               // "ख"
क्रमित_फर्श(म, २५)              // 20  (सबसे बड़ी कुंजी <= 25)
क्रमित_छत(म, २५)                // 30  (सबसे छोटी कुंजी >= 25)
क्रमित_श्रेणी(म, १५, ३५)         // [20, 30]
क्रमित_रैंक(म, ३०)              // 2   (30 से छोटी कुंजियाँ)
क्रमित_चयन(म, ०)                // 10  (सबसे छोटी कुंजी)
```

`शब्दकोश` अक्रमित है (`कुंजियाँ()` का क्रम गारंटी नहीं) — यह मॉड्यूल वही
मानचित्र **क्रमित पहुँच** के साथ देता। निरूपण: AVL संतुलित द्विआधारी
खोज-वृक्ष (नोड = शब्दकोश `{"कुंजी","मूल्य","बायाँ","दायाँ","ऊँचाई","आकार"}`;
"आकार" = उपवृक्ष की नोड-गिनती, इसी से रैंक/चयन O(log n))। API:
`क्रमित_बनाओ`, `क्रमित_रखो` (नई कुंजी पर सत्य, अद्यतन पर असत्य),
`क्रमित_पाओ` / `क्रमित_पाओ_या` / `क्रमित_है` / `क्रमित_हटाओ`, `क्रमित_आकार` /
`खाली_है` / `खाली_करो`, `क्रमित_न्यूनतम_कुंजी` / `अधिकतम_कुंजी`,
`क्रमित_न्यूनतम_निकालो` / `अधिकतम_निकालो` (`[कुंजी, मूल्य]` लौटाकर हटाते —
priority-queue की तरह), पड़ोसी: `क्रमित_फर्श` (<=) / `छत` (>=) / `पिछला` (<) /
`अगला` (>), `क्रमित_रैंक` / `क्रमित_चयन`, सूचियाँ: `क्रमित_कुंजियाँ` /
`क्रमित_मूल्य` / `क्रमित_युग्म` / `क्रमित_श्रेणी` (बंद अंतराल), और परीक्षण/डीबग को
`क्रमित_ऊँचाई` / `क्रमित_जाँच` (BST-क्रम + AVL-संतुलन + दर्ज ऊँचाई/आकार की
पुनर्जाँच)। समय: रखो/पाओ/है/हटाओ/पड़ोसी/रैंक/चयन/न्यूनतम/अधिकतम सब O(log n);
कुंजियाँ/मूल्य/युग्म O(n); श्रेणी O(log n + k)।

कुंजियाँ सब `संख्या` या सब `पाठ` (पाठ की तुलना कोडबिंदु-वार — .NET
`StringComparer.Ordinal` से सत्यापित); मिश्रित प्रकार `क्रमित_रखो` में त्रुटि
देता, पढ़ने वाले कार्य बेमेल कुंजी को "नहीं मिली" मानते। मूल्य `मान` (कोई भी प्रकार)।
सूचियाँ (कुंजियाँ आदि) हमेशा नई बनकर लौटतीं, जगह पर नहीं बदलतीं।

⚠️ **native में `०` और `शून्यम्` अलग नहीं दिखते** (tagged मान नहीं — सीमाएँ #6)।
"नहीं मिला" के लिए `शून्यम्` लौटाने वाले कार्य (पाओ / न्यूनतम_कुंजी / फर्श ...)
इसलिए तब अस्पष्ट हैं जब मूल्य या कुंजी खुद ० हो सकती है — वहाँ पहले
`क्रमित_है` / `क्रमित_खाली_है` से जाँचो, या `क्रमित_रैंक` + `क्रमित_चयन` से
चलो, या `क्रमित_पाओ_या` लो। कुंजी `०` स्वयं मान्य है और तीनों बैकएंड पर
सही क्रम पाती (native में `प्रकार(०)` "शून्यम्" कहता — इसे संख्या ० माना जाता);
स्पष्ट `शून्यम्` कुंजी interpreter में त्रुटि देती, native में ० बन जाती।

देखो: `भाषा_परीक्षण/stdlib/क्रमित_मानचित्र_परीक्षण.सूत्र` (179 जाँच —
नियतात्मक: रखो/पाओ/अद्यतन, हटाओ के तीनों मामले (पत्ता / एक-बच्चा /

## विन32.सूत्र — Win32 विंडो/GDI बाइंडिंग (`विदेशी` पर आधारित)

`यूआई.सूत्र` की चित्र_सूची (render-command list) को एक असली Win32 खिड़की में
खींचता — पहला असली renderer backend। `rules.md` §2a का `विदेशी` उपयोग करता;
compiler में कोई विशेष सुविधा नहीं जोड़ी।

```sutra
आयात "पुस्तकालय/यूआई.सूत्र";
आयात "पुस्तकालय/विन32.सूत्र";

कार्य मुख्य() {
    संख्या इंस्ट = विं_मॉड्यूल_पता(०);
    पाठ वर्ग_नाम = "MeraSutraApp";
    शब्दकोश वग = विं_वर्ग_बनाओ(वर्ग_नाम, विं_डिफ़ॉल्ट_प्रक्रिया_पता(), इंस्ट);
    विं_वर्ग_पंजी(वग["पता"]);
    संख्या ख = विं_खिड़की_बनाओ_सरल(वर्ग_नाम, "मेरी खिड़की", ६४०, ४८०, इंस्ट);
    विं_दिखाओ(ख, विं_दिखा_सामान्य());

    संख्या डीसी = विं_डीसी_लो(ख);
    विं_चित्र_खींचो(डीसी, यूआई_चौखटा(दृश्य(), यूआई_अवस्था_नई(), ६४०, ४८०));
    विं_डीसी_छोड़ो(ख, डीसी);

    विं_लूप_चलाओ(ख);   // बंद (X) दबाने तक — ~20fps poll, कोई custom WNDPROC नहीं
}
```

**काम कैसे करता (कोई compiler-सुविधा नए सिरे से नहीं):**
- `WNDCLASSA`/`RECT`/`MSG` structs — Sutra `पाठ` को कच्चे byte-buffer के रूप
  में इस्तेमाल करके `अंतर्_लिख8`/`अंतर्_लिख1` (पहले से बिल्टिन) से पैक किए जाते;
  `विदेशी_पता(वस्तु)` से पता निकलता।
- `DefWindowProcA` का पता (WNDCLASSA.lpfnWndProc के लिए) **`GetModuleHandleA`
  + `GetProcAddress`** से रनटाइम पर लिया जाता — कोई function-pointer/address-of
  compiler-सुविधा नहीं चाहिए, दोनों ख़ुद `विदेशी` कॉल हैं।
- बंद-बटन (X) दबाने पर `DefWindowProcA` खुद खिड़की नष्ट करता; लूप `IsWindow`
  से हर 50ms जाँचता — तो custom WNDPROC (और उसके लिए Sutra-फलन का पता लेने
  की सुविधा) की ज़रूरत ही नहीं पड़ी।
- **यूनिकोड:** शीर्षक + चित्रित पाठ दोनों `CreateWindowExW`/`TextOutW`
  (wide) से — UTF-8→UTF-16 रूपांतरण मौजूदा `सूत्र_तल_यूटीएफ_चौड़ा` (तल.s,
  फ़ाइल-पथ हेतु पहले से बना) पर। असली खिड़की में देवनागरी सही सत्यापित।

देखो: `उदाहरणानि/खिड़की_पैनल.सूत्र` — settings-panel असली खिड़की में।

## थ्रेड.सूत्र — असली OS थ्रेड + Mutex (`विदेशी` + `फलन_पता` पर आधारित)

```sutra
आयात "पुस्तकालय/थ्रेड.सूत्र";

कार्य कार्य_खंड(संख्या पैरामीटर) {
    // ⚠️ सिर्फ़ संख्या-गणित + अंतर्_पढ़*/लिख* + विदेशी कॉल — कोई सूची/पाठ/
    // शब्दकोश आवंटन नहीं (GC single-threaded है, rules.md §2b देखो)
    परत् ०;
}
कार्य मुख्य() {
    संख्या ह = थ्रेड_बनाओ(फलन_पता(कार्य_खंड), ०);
    थ्रेड_प्रतीक्षा_बंद(ह);   // join

    संख्या म्यू = म्यूटेक्स_नया();
    म्यूटेक्स_लो(म्यू); ... म्यूटेक्स_छोड़ो(म्यू);
}
```

| कार्य | काम |
|---|---|
| `थ्रेड_बनाओ(फलन_पता(...), पैरामीटर)` | नया OS थ्रेड चलाता, हैंडल लौटाता (0=विफल) |
| `थ्रेड_प्रतीक्षा(हैंडल)` · `थ्रेड_बंद(हैंडल)` | INFINITE प्रतीक्षा · हैंडल मुक्त |
| `थ्रेड_प्रतीक्षा_बंद(हैंडल)` | दोनों एक साथ (join) |
| `सोओ(मिलीसेकंड)` | वर्तमान थ्रेड को रोके |
| `म्यूटेक्स_नया()` · `म्यूटेक्स_लो/छोड़ो/बंद(हैंडल)` | साझा कच्ची-मेमोरी की सुरक्षा |

**पहली बार सिद्ध:** `उदाहरणानि/थ्रेड_परीक्षण.सूत्र` — 4 असली OS थ्रेड, हर एक
100,000 बार mutex-सुरक्षित एक साझा counter बढ़ाता; अंतिम गिनती ठीक 400,000
(कोई race नहीं)। `फलन_पता` (rules.md §2b) — नई compiler-सुविधा, सिर्फ़ इस
काम के लिए — `CreateThread` को असली, चलाने-योग्य Sutra-फलन का पता देती।

## संजाल.सूत्र — TCP क्लाइंट संजाल + HTTPS/TLS (`विदेशी` पर आधारित)

```sutra
आयात "पुस्तकालय/संजाल.सूत्र";

// plain HTTP — Winsock2 (ws2_32) पर सीधे
संजाल_आरंभ();                                       // प्रक्रिया-जीवनकाल में एक बार
पाठ पृष्ठ = संजाल_एचटीटीपी_गेट("example.com", ८०, "/");
संजाल_सफाई();

// HTTPS — WinHTTP (असली TLS + प्रमाणपत्र-सत्यापन) पर
पाठ सुरक्षित_पृष्ठ = संजाल_एचटीटीपीएस_गेट("example.com", ४४३, "/");

// या हाथ से, नियंत्रण चाहिए तो (plain HTTP पथ):
शब्दकोश सं = संजाल_होस्ट_जोड़ो("example.com", ८०);   // या संजाल_जोड़ो("93.184.216.34", ८०)
संजाल_भेजो_पाठ(सं["सॉकेट"], "GET / HTTP/1.1\r\nHost: example.com\r\nConnection: close\r\n\r\n");
पाठ उत्तर = संजाल_सब_पाओ_पाठ(सं["सॉकेट"]);
संजाल_बंद(सं["सॉकेट"]);
```

विन32.सूत्र/थ्रेड.सूत्र जैसा — `विदेशी` पर आधारित असली OS क्षमता, पर
struct-packing (`sockaddr_in`, `hostent`)/byte-order/DNS-पार्सिंग/API-सतह
की सारी लॉजिक मौलिक Sutra कोड, किसी socket/HTTP-library का पोर्ट नहीं।

**दो अलग रास्ते, दो अलग DLL:**

| कार्य (plain HTTP, `ws2_32`) | काम |
|---|---|
| `संजाल_आरंभ()` · `संजाल_सफाई()` | Winsock शुरू/बंद (`WSAStartup`/`Cleanup`) |
| `संजाल_जोड़ो(आइपी, पोर्ट)` | संख्यात्मक IPv4 पते से TCP कनेक्ट |
| `संजाल_होस्ट_जोड़ो(होस्टनाम, पोर्ट)` | DNS (`gethostbyname`) + कनेक्ट एक साथ |
| `संजाल_होस्ट_खोजो(होस्टनाम)` | सिर्फ़ DNS रिज़ॉल्यूशन, रॉ IPv4 संख्या (−1 = विफल) |
| `संजाल_भेजो(सॉकेट, बाइट्स)` · `_भेजो_पाठ` | कच्चे बाइट्स / UTF-8 पाठ भेजो |
| `संजाल_पाओ(सॉकेट, अधिकतम)` · `_सब_पाओ(_पाठ)` | एक `recv()` · बंद होने तक सब पढ़ो |
| `संजाल_बंद(सॉकेट)` | सॉकेट बंद करो |
| `संजाल_एचटीटीपी_गेट(होस्ट, पोर्ट, पथ)` | सुविधा — पूरा राउंड-ट्रिप एक कॉल में |

| कार्य (HTTPS/TLS, `winhttp`) | काम |
|---|---|
| `संजाल_सुरक्षित_सत्र_बनाओ()` | `WinHttpOpen` — एक सत्र, कई निवेदनों के लिए |
| `संजाल_सुरक्षित_जोड़ो(सत्र, होस्ट, पोर्ट)` | `WinHttpConnect` |
| `संजाल_सुरक्षित_निवेदन_बनाओ(जुड़ाव, विधि, पथ, सुरक्षित)` | `WinHttpOpenRequest` — `सुरक्षित=सत्य` पर TLS |
| `संजाल_सुरक्षित_भेजो(निवेदन)` · `_उत्तर_पाओ` | `WinHttpSendRequest`/`ReceiveResponse` |
| `संजाल_सुरक्षित_स्थिति_कोड(निवेदन)` | HTTP स्थिति कोड (200, 404, ...) |
| `संजाल_सुरक्षित_सब_पाओ(_पाठ)(निवेदन)` | पूरा उत्तर-शरीर पढ़ो |
| `संजाल_सुरक्षित_बंद(हैंडल)` | कोई भी WinHTTP हैंडल बंद करो |
| `संजाल_एचटीटीपीएस_गेट(होस्ट, पोर्ट, पथ)` | सुविधा — पूरा HTTPS राउंड-ट्रिप एक कॉल में |
| `संजाल_सुरक्षित_जुड़ाव_सफल(होस्ट, पोर्ट, पथ)` | सिर्फ़ सफल/विफल (प्रमाणपत्र-जाँच के लिए उपयोगी) |

**⚠ TLS ख़ुद लागू नहीं किया — जानबूझकर।** RSA/ECDHE कुंजी-विनिमय, AES-GCM,
X.509 प्रमाणपत्र-सत्यापन हाथ से लिखना "अपना क्रिप्टो मत बनाओ" वाले
उद्योग-नियम के ख़िलाफ़ है — ग़लत होने पर असली सुरक्षा-भेद्यता बनता है, SHA-256
या PRNG जैसे "ग़लत होने पर सिर्फ़ ग़लत जवाब" मामलों से मौलिक रूप से अलग
जोखिम-श्रेणी। इसकी जगह **WinHTTP** (`winhttp.dll`) — Windows का अपना,
production-grade, पहले से-परीक्षित TLS कार्यान्वयन — `विदेशी` से बुलाया,
बिल्कुल उसी सिद्धांत पर जो kernel32/user32/ws2_32 कॉल करने में लागू होता
है (OS-दी क्षमता इस्तेमाल करना कॉपी नहीं)। प्रमाणपत्र-सत्यापन डिफ़ॉल्ट
चालू रहता है — कहीं बंद नहीं किया गया।

**v1 दायरा (जानबूझकर सीमित):** सिर्फ़ TCP क्लाइंट (connect/send/recv), सिर्फ़
IPv4, कोई server/listen/accept नहीं, DNS के लिए पुराना पर सरल
`gethostbyname` (`getaddrinfo` नहीं — IPv4-only v1 के लिए काफ़ी)।

⚠ **सिर्फ़ x86 डिफ़ॉल्ट + `--release` (LLVM) बैकएंड — दुभाषिया (`sutra.exe
run`) पर काम नहीं करता।** ये विन32.सूत्र/थ्रेड.सूत्र जैसा ही, नया गैप नहीं —
`विदेशी`/FFI दुभाषिया में कभी लागू ही नहीं हुआ (कोई native-DLL-कॉल तंत्र
नहीं), सिर्फ़ दोनों compiled बैकएंड पर (जो असली MS x64 ABI कॉल बनाते हैं)।

**असली इंटरनेट पर सिद्ध किया** (सिर्फ़ मॉक नहीं): example.com को संख्यात्मक
IP और होस्टनाम दोनों से plain HTTP GET, `gethostbyname` का `hostent`-
पार्सिंग PowerShell के `.NET` resolver से मिले उसी exact IP तक पहुँचा
(क्रॉस-चेक किया)। **HTTPS का असली सुरक्षा-गुण भी सिद्ध किया, सिर्फ़ "कनेक्ट
हो गया" नहीं**: `expired.badssl.com` (जानबूझकर expired प्रमाणपत्र वाला
टेस्ट-सर्वर) से जुड़ाव सही से **अस्वीकृत** होता (PowerShell के अपने `.NET`
TLS-सत्यापन से मिलान करके क्रॉस-चेक किया), जबकि example.com जैसा वैध
प्रमाणपत्र सामान्य रूप से स्वीकृत होता रहता है — यही साबित करता है कि
प्रमाणपत्र-सत्यापन असल में हो रहा है, बायपास नहीं हुआ। `भाषा_परीक्षण/stdlib/
संजाल_परीक्षण.सूत्र` — 20 जाँच: नियतात्मक बफर-सहायक round-trip (संजाल
नहीं चाहिए) + असली HTTP GET + DNS रिज़ॉल्यूशन (सफल + जानबूझकर-अमान्य दोनों)
+ असली HTTPS GET (status-कोड सटीक 200 सहित) + प्रमाणपत्र-सत्यापन (expired
अस्वीकृत + वैध स्वीकृत) + त्रुटि-हैंडलिंग (बंद पोर्ट, क्रैश नहीं) — **x86 +
`--release` दोनों पर 20/20**। ⚠ बाकी stdlib के विपरीत यह फ़ाइल असली संजाल
कनेक्टिविटी पर निर्भर — ऑफ़लाइन चलाने पर कुछ जाँचें असफल दिखेंगी, बग नहीं।

## सीमाएँ (सूत्र की वर्तमान भाषा-सीमाएँ, पुस्तकालय की नहीं)

1. **प्रथम-श्रेणी कार्य नहीं** → `map` / `filter` / `reduce` जैसे उच्च-क्रम
   कार्य नहीं। इसलिए `योग`/`समाहित`/`क्रमबद्ध` जैसे ठोस रूप ही मिलते हैं।
2. **विधि-कॉल का लक्ष्य static वर्ग से हल होता** (native) → किसी फलन का
   परिणाम या `मान`-typed चर पर `.विधि()` नहीं चलता। इसलिए `संघ`/`प्रतिच्छेद`/
   `अंतर` समुच्चय नहीं, **सूची** लौटाते हैं (चाहिए तो `समुच्चय_से_सूची(...)`
   से दुबारा लपेटो)।
3. **`वर्गनाम चर = ...` local-declaration पार्स नहीं होता** — सिर्फ़ param
   type के रूप में वर्ग-नाम चलता है। इसलिए helper लो जो `समुच्चय` param लेता।
4. **बूल-लौटाने वाला user कार्य `लिखतु()` में `1`/`0` छापता** (native) —
   user-function return-type inference अभी नहीं। मान सही है (`यदि` में चलता)।
5. **`हटाएं(शब्दकोश, कुंजी)` native में नहीं** — `कुंजी_हटाओ` (शब्दकोश.सूत्र)
   प्रयोग करो।
6. **tagged मान नहीं** — native में बूल/दशमलव जब `मान`-typed चर या
   सूची/शब्दकोश-तत्व बनते, संख्या से अलग नहीं होते: `प्रकार()` गलत, और
   `× − ÷` (float dynamic अंकगणित) पूर्णांक जैसा चलता। हल: float-गणित के
   लिए चर/param `दशमलव`-typed रखो और float-साहित्य लिखो (`10.0` न कि `10`)।
   सुधार: *`दशमलव`-घोषित लक्ष्य* (चर-प्रारंभ/असाइनमेंट/`दशमलव`-पैरामीटर का तर्क)
   में अब `मान`-typed operands का `+ − × ÷` सही float चलता; बिना ऐसे लक्ष्य वाली
   अभिव्यक्ति (`जोड़ें(x, f()+g())`, `"" + f()`, तुलना) में सीमा जस-की-तस।
7. **`स्व.क्षेत्र[i] = v` पार्स नहीं होता** — सूची/शब्दकोश-क्षेत्र को स्थानीय
   चर में लेकर (`मान अ = स्व.क्षेत्र; अ[i] = v;`) — reference है तो क्षेत्र बदलता।
8. **ऋण-रहित पूर्णांक < 2³¹** — `2463534242` जैसा साहित्य interpreter में
   `बड़ा_पूर्णांक` माना जाता; `संख्या`-declared global के initializer में
   2³¹ से छोटा मान दो।
