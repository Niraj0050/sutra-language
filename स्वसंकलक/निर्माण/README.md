# स्वसंकलक/निर्माण/ — बूटस्ट्रैप बीज (Bootstrap Seed)

यह निर्देशिका सूत्र संकलक को **C++ host के बिना** खड़ा करने की सामग्री रखती है।

## सामग्री

| सञ्चिका | क्या है |
|---|---|
| `मूल_संकलन.s` | जमी हुई x86-64 असेम्बली — सूत्र native संकलक (`स्वसंकलक/मूल_संकलन.सूत्र` + आयातित) का पूर्ण output, स्वयं सूत्र संकलक द्वारा उत्पन्न। यही "बीज" है। |
| `sutra_runtime.c` | न्यूनतम C runtime (allocator, GC, string/array/dict, print, exceptions, file I/O)। हर सूत्र binary में लिंक होता है। भविष्य में सूत्र में लिखा जाएगा। |

## प्रयोग

रेपो-मूल से:

```powershell
powershell -ExecutionPolicy Bypass -File bootstrap.ps1
```

यह:
1. `sutra_runtime.c` को `.o` में संकलित करता है (`gcc -c` — केवल C, C++ नहीं)
2. `मूल_संकलन.s` को `as` से असेम्बल करता है
3. `gcc` (केवल linker रूप में) से जोड़कर `seed_सूत्रसंकलक.exe` बनाता है
4. उस seed संकलक से current `.सूत्र` स्रोत को संकलित करके `सूत्रसंकलक.exe` बनाता है
5. fixed-point जाँच — seed और ताज़ा संकलक समान असेम्बली दें

**आवश्यक:** MSYS2 ucrt64 (`C:\msys64\ucrt64\bin`) — `as`, `gcc`, `ld`।
C++ संकलक, `sutra.exe` (C++ host), या `संकलक/` की कोई आवश्यकता नहीं।

## बीज कब ताज़ा करें

`मूल_सर्जक.सूत्र` / `विश्लेषक.सूत्र` / `लेखक.सूत्र` / `मूल_संकलन.सूत्र` में
codegen-प्रभावी बदलाव के बाद, ताकि नया क्लोन नई क्षमताओं से शुरू हो।
पुराना बीज भी काम करता है — वह बस पुराने बिंदु से शुरू करता है, और
चरण 4 में ताज़ा संकलक फिर भी current स्रोत से बनता है।

ताज़ा करने के लिए (एक कार्यशील संकलक चाहिए — seed या पूर्व-निर्मित):

```powershell
.\सूत्रसंकलक.exe स्वसंकलक\मूल_संकलन.सूत्र
copy /y sutra_native_temp.s स्वसंकलक\निर्माण\मूल_संकलन.s
```

तथा `sutra_runtime.c` बदलने पर उसकी प्रति भी अद्यतन करें:

```powershell
copy /y संकलक\src\compiler\sutra_runtime.c स्वसंकलक\निर्माण\sutra_runtime.c
```
