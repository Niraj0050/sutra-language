## 2. Documentation Completion Criteria

To declare the Sutra documentation ecosystem "complete", the following metrics must be satisfied:

1. **Language Reference Completeness**: Every keyword, primitive type, syntax rule, and standard library API must have a corresponding reference section detailing options and examples.
2. **Compiler Architecture Completeness**: The compiler documentation must cover all stages from lexing to linking, explaining how data shifts through the pipeline.
3. **Runtime/Memory Completeness**: The garbage collector algorithm, heap layouts for strings, lists, objects, and ABI interfaces must be fully specified.
4. **Self-Hosting Completeness**: The bootstrap generations flow (Gen 1 -> Gen 3) must be documented with instructions to compile and verify the compiler.
5. **Standard Library reference**: Complete function signatures, parameter descriptions, return value types, and usage code blocks for all Math, String, List, and I/O functions.
6. **Testing/Verification Documentation**: Explaining stability checking scripts (`run_tests.ps1`), self-hosting verification tests (`verify_compiler_self.ps1`), and diagnostic error codes.
7. **Developer Documentation**: Comprehensive workspace layouts, setup configurations, and conventions for developer onboarding.
8. **Cross-Link Validation**: Standard documentation checks must verify that all internal links are relative, unbroken, and target valid files.
9. **Example Validation**: All code examples in documentation must be compiled with the current self-hosted compiler version to prevent code-example rot.
10. **Factual Consistency Audit**: Checks ensuring that no document contradicts the Git status representation, test parameters, or verified features.
